This is a test build for a small group of testers. It is not a public release.

Download the file for your computer below. The steps for opening it the first time are in [docs/install.md](https://github.com/peterhudson/timegrapher/blob/main/docs/install.md). The builds are unsigned, so macOS and Windows will warn you once.

This release fixes bugs and closes gaps found since 0.3.0. There are no new panes.

## Before you start: takes saved by 0.4.0 don't open in 0.3.0

Takes saved by 0.4.0 note in their `session.toml` whether the lift angle was entered or assumed (a new `lift_known` line). 0.3.0 and its Claude Desktop extension don't know that line:
- 0.3.0's command line tool refuses the take.
- 0.3.0's app opens it with default settings, so it loses the watch, lift angle and positions.

The sound files are not affected. 0.4.0 opens takes saved by 0.3.0 as before. If you need to open a 0.4.0 take in 0.3.0, delete its `lift_known` line. Update the app, the command line tool and the extension together.

## Saving and recording
- **Saving is all or nothing.** If any file fails to write, the copy saved earlier is left as it was and the app says what failed. If even that fails, it names the folder holding the recovery files.
- **When recording fails** (the disk fills up, for example), recording stops. A warning names the folder whose files may need recovering by hand, and a RECORDING-ERROR.txt note is left in it. Save, Save Again and Resume are switched off for that session so an earlier saved take is not touched. **Leave Files and Continue** and **Leave Files and Quit** let you carry on. A microphone that simply disconnects can still be resumed.
- **Unsaved changes.** New Session, Open and Quit now also warn about unsaved changes to the watch details or position history, not only unsaved sound.
- **Paused takes.** After a pause and resume, saved positions, including Positions Test start and end points, are placed at the right time in the sound. Before, they could be shifted by the length of the pause.

## Opening saved takes
- Replaying a saved take restores its positions and settling periods. Readings no longer run across a saved move or the end of a settling period, and choosing a position shows only that position's stretches.
- A `session.toml` that can't be read, or that holds an impossible value such as a beat rate of 0 or a lift angle of 0, now stops the take opening. A red message names the file and the value. 0.3.0 used default settings instead without saying so. Folders without a `session.toml` open as before.

## Readings and charts
- Readings and the Steadiness views no longer join across a known jump in the beat log or a change of position, even when separate visits to one position are put together.
- The FFT charts show how much of the input was available, and mark peak heights where some was missing.
- In the session report, the rate says whether it is against the sound card's clock or clock corrected. For a clock-corrected rate, the comparison against a reference rate is left out, with a note.

## Calibres and clock correction
- If your calibre file can't be read, **Manage Calibres** says so. Changes are then kept only until you quit, and the file is never written over. The built-in calibres still work.
- The command line tool and the assistant now accept your own calibres and their other names, as the app does. A calibre name that isn't known is refused rather than ignored.
- A damaged clock-correction file is reported when you start the microphone or run a `clock` command, and is never written over. Before, it was treated as empty.

## Command line
- Lengths (`--seconds`, `--minutes`) and settings (`--bph`, `--lift`, `--escape-teeth`, `--card-ppm`) of zero, below zero or not a number are refused before the microphone opens or any work starts.
- Given a folder, `long`, `series` and the session readings take the files in the order `session.toml` lists them, then by number (part 2 before part 10), as the app does.
- `series --json` reports the clock correction it applied.
- `record` won't add a take with an entered lift angle to a session whose lift angle was assumed. Use another folder.

## For AI assistants
- **A wrong number fixed:** the chat's analysis summary could use a different clock correction from the command line tool's. It now uses the same one and says which it used.
- A command that fails is reported to the assistant as a failure even if it printed results.
- The chart view in the chat waits until Claude is ready, and says so if it can't connect.
- Recordings and analyses started from the chat have time limits and are cleaned up afterwards. Folder names such as `~/Takes` are expanded before use.
- The steadiness and FFT results say which clock correction applied and how much input was available.

## Building from source
Building from source now needs Rust 1.90 or later.
